# 🧅 대파(대용량 파티원) 기획안

> 공고 → 참여 → 채팅 → 정산까지 한 번에 끝내는 동네 공동구매(공구) 플랫폼

| 항목 | 내용 |
| --- | --- |
| 개발 기간 | 2026.08.10 ~ 2026.08.12 (3일) |
| 팀 구성 | 4인 |
| 문서 버전 | v1.0 (2026.08.10) |

---

## 1. 문제 정의

- 혼자 시키면 배달비가 아깝고, 최소 주문 금액을 못 맞춘다.
- 대용량 생필품·식료품은 1인 가구가 사기엔 양이 너무 많다.
- 기존에는 아파트 단톡방/당근 등에서 모집 → **정산이 수기**라서 금액 계산, 입금 확인, 리마인드가 전부 사람 손을 탄다.

**→ 대파는 모집부터 정산까지의 전 과정을 한 서비스 안에서 자동화한다.**

## 2. 타깃 사용자

- 배달비를 나누고 싶은 1인 가구 / 자취생
- 대용량 상품을 나눠 사고 싶은 이웃 (코스트코, 창고형 마트 등)
- 총무 역할이 귀찮아서 공구를 안 여는 잠재 주최자

## 3. 핵심 컨셉

1. **버튼 한 번 참여** — 공고 카드에서 즉시 참여, 채팅방 자동 입장
2. **실시간** — 참여 인원 진행바, 남은 시간, 상태 배지가 실시간 반영
3. **정산 자동화** — 영수증 인식 → 1/N 계산 → 입금 체크리스트 → 리마인드
4. **대파페이** — 지갑 잔액으로 정산 요청 자동 결제, 계좌/토스 링크 송금도 지원

## 4. 기능 명세

### 4.0 로그인 · 회원가입 (온보딩)

- **로그인**: 이메일 + 비밀번호. 로그인 ↔ 회원가입 모드 전환
- **회원가입**: 닉네임 + 이메일/비밀번호 + **동네 인증**
  - 동네 인증은 3일 범위에서 **원클릭 목(mock) 인증**("역삼동 인증 완료 ✓") — 실제 GPS 인증은 범위 제외
- **소셜 로그인**: 깃허브 · 구글 버튼 (프로토타입은 클릭 시 즉시 입장, 실연동은 Supabase OAuth로 추후)
- 레이아웃: 좌측 브랜드 패널(로고 + 서비스 가치 3줄) + 우측 인증 카드
- **로그아웃**: 프로필 팝오버에서 → 로그인 화면 복귀
- 인증 상태는 Supabase Auth 세션 기반으로 구현 (연동 작업: 이슈 #2)

### 4.1 공구 공고 올리기

- 카테고리 선택: `식료품` `배달음식` `생활용품` `대량구매` `기타`
- 공통 입력: 제목, 설명, 총 금액(예상), 목표 인원, 마감 시간, (선택) 이미지
- **배달음식 전용 폼**: 가게 링크 입력 + 짧은 마감 프리셋(15분/30분/1시간)
- 작성 중 우측(모바일: 하단)에 **실시간 카드 미리보기** 표시
- 등록 시 **공구 채팅방 자동 생성** + 주최자 자동 입장

### 4.2 공구 목록 · 상세 (실시간)

- 목록: 카테고리 필터, 상태 필터, 카드형 리스트
- 카드/상세 공통 실시간 요소
  - 목표 인원 대비 현재 참여자 **진행바**
  - 남은 시간 **카운트다운**
  - 상태 배지: `모집중` `마감임박` `정산중` `마감`
    - `마감임박`은 별도 상태가 아니라 **마감 1시간 전부터 파생 표시** (배지 기준. 알림은 30분 전 발송)
  - **1인당 금액 자동 계산**: `총 금액 ÷ (현재 참여자 수)` 실시간 갱신
- **버튼 한 번 즉시 참여** → 참여 즉시 채팅방 입장 + 시스템 메시지 발생
- **선착순 마감 (확정)**: 목표 인원 = 정원. 목표 도달 순간 자동으로 `정산중` 전환 + 추가 참여 차단
  - 동시 클릭 레이스 컨디션 방지를 위해 참여 처리는 **서버에서 원자적으로** 수행한다
    (`UPDATE group_buys SET joined = joined+1 WHERE id=$1 AND joined < goal AND status='recruiting' RETURNING joined` — 행이 없으면 "마감" 응답)

### 4.3 총 금액 변경

- 정산 시작 전까지 **주최자만** 총 금액 수정 가능
- 변경 시: 참여자 전원에게 알림 + 1인당 금액 즉시 재계산 + 채팅방 시스템 메시지
- **정산 시작 후에는 금액 잠금** (수정 UI 비활성화 + 서버에서 거부)

### 4.4 채팅 커뮤니티

- **동네 라운지**: 전체 공개 자유 수다방 (기본 입장)
- **공구별 채팅방**: 공고 등록 시 자동 생성, 참여자만 입장
- **공구 카드 공유**: 라운지/다른 방에 공구 카드를 말풍선으로 전송 → 카드에서 바로 참여
- **시스템 메시지**: 참여/탈퇴/마감/금액 변경/정산 시작/입금 완료 이벤트 표시
- **채팅방 검색**: 방 이름/공구 제목 기준 검색

### 4.5 정산 시스템

- 주최자가 `정산 시작` → 공구 상태 `정산중` 전환 + 금액 잠금
- **총액 확정**: 주최자가 최종 총액을 수동 입력 + (선택) 영수증 사진 첨부
  - ⏸ **영수증 자동 인식(Claude API 비전)은 보류** — 3일 범위에서 제외, 여유 시 후순위 검토
- 분배 방식
  - 기본: **균등 1/N**
  - 개별 금액 조정 가능 (단, **배달비는 항상 자동 균등 분배**)
  - 계산식: `개인 부담금 = 개인 항목 금액 + (배달비 ÷ 참여자 수)`
- **총액 확정 절차**: 영수증 사진이 있으면 첨부로 증빙, 없으면 **참여자 동의 투표**(과반 동의 시 확정)
- **입금 현황 체크리스트**: 참여자별 입금 여부 표시, 미입금자 **리마인드 알림** 전송
- 전원 입금 완료 → 공구 상태 `마감`

### 4.6 대파페이 지갑

- 잔액 조회 / 충전 / 출금 (실제 PG 없이 모의 충전)
- **정산 요청 자동 결제**: 잔액이 충분하면 원터치 결제 → 입금 체크리스트 자동 반영
- 이용 내역 (충전/출금/결제/수령)
- 잔액 부족 시: 주최자의 **계좌번호 복사 / 토스 링크**로 외부 송금 → 수동 입금 확인

### 4.7 프로필

- **팝오버 방식** (아바타 클릭 시)
- 참여 횟수 / 주최 횟수
- **정산 신뢰도 배지** (기한 내 입금율 기반)
- 내 공구 내역 (참여 중 / 주최 중 / 완료)

### 4.8 설정

- 알림 설정: 마감 임박 알림, 입금 요청 알림 on/off
- 정산 받을 계좌 등록
- 기본 송금 앱 선택 (토스 등)
- 계정 관리 (닉네임 변경, 로그아웃, 탈퇴)

## 5. 공구 상태 흐름

```
모집중 (recruiting)
  │  마감 1시간 전 → 배지만 "마감임박"으로 표시 (파생 상태)
  ▼  ① 목표 인원 도달(선착순 정원 참) ② 주최자 "정산 시작" ③ 마감 시간 도달
정산중 (settling)   ← 총 금액 잠금 · 추가 참여 불가
  ▼  전원 입금 완료
마감 (completed)

* 어느 단계에서든 주최자 취소 → 취소 (canceled)  ※ 모집중·정산중에서만. 마감(completed) 후에는 못 한다
* 목표 인원 = 정원(선착순). 초과 모집 없음 — 참여 INSERT는 서버에서 원자적으로 정원 검사
```

취소 경로(#29)는 상세 화면의 주최자 전용 "🚫 공구 취소" 버튼 → 확인 → `cancel_group_buy(id)` RPC 다.
`group_buys.status` 는 컬럼 GRANT 로 클라이언트 UPDATE 가 막혀 있어 이 `security definer` RPC 로만 `canceled` 가 된다.
RPC 는 주최자 본인 + `status in (recruiting, settling)` 을 확인하고, 채팅방 시스템 메시지(`kind='sys'`)와
참여자 전원 알림(`type='cancel'`)을 함께 넣는다. 취소된 공구의 상태 배지는 `마감` 으로 표시하고(배지 문구 4종 고정),
홈 목록에서는 감춘다 — 내 공구·채팅방에는 기록으로 남는다.

정산중에 취소하면 **대파페이로 이미 낸 사람은 자동 환불**된다. RPC 가 해당 공구의 `wallet_transactions.kind='pay'`
행을 되감아 `wallets.balance` 를 복구하고 `receive` 내역·환불 알림을 남긴다(환불 알림을 받은 사람은 취소 알림에서 제외).
계좌·토스로 낸 사람은 앱 밖 송금이라 환불이 불가능해서, 채팅방에 주최자 직접 환불 안내 메시지를 남긴다.

## 7. 데이터 모델 (Supabase Postgres)

> 실제 DDL은 **[supabase/schema.sql](../supabase/schema.sql)** 이 단일 출처. 아래는 요약이며 스키마 변경 시 함께 갱신한다.

```
profiles            id(=auth.users.id), nickname, avatar_url, dong, bank_account,
                    transfer_app, notify_deadline, notify_payment,
                    trust_score, created_at
wallets             user_id, balance
group_buys          id, host_id, title, description, category, store_link,
                    total_amount, delivery_fee, min_order_amount(배달음식 전용),
                    goal, joined, deadline, place,
                    status(recruiting|settling|completed|canceled), created_at
participations      id, group_buy_id, user_id, note, amount_due, is_paid,
                    paid_at, joined_at            -- unique(group_buy_id, user_id)
chat_rooms          id, type(lounge|group_buy), group_buy_id?, name
messages            id, room_id, user_id?, kind(text|sys|card),
                    content, payload(jsonb), created_at
settlements         id, group_buy_id, total_amount, delivery_fee, receipt_url,
                    overrides(jsonb, 확정 전 손수 조정한 참여자별 금액),
                    status(pending|confirmed), confirmed_at
settlement_votes    settlement_id, user_id, agree(boolean)
wallet_transactions id, user_id, kind(charge|withdraw|pay|receive), amount,
                    group_buy_id?, title, created_at
notifications       id, user_id, type, payload(jsonb), is_read, created_at
```

- 상태값은 `recruiting|settling|completed|canceled`. `lib/types.ts`의 `DealStatus`도 같은 값이라 매핑 레이어가 없다.
  `마감임박`은 DB 상태가 아니라 `deadline` 1시간 전부터 UI 파생.
- `goal` = 목표 인원 = 정원, `joined` = 현재 참여 수(주최자 포함, 기본 1).
- **참여는 `join_group_buy(id)` RPC 로만** 한다. 원자적 `UPDATE ... WHERE joined < goal` 로
  정원 초과·중복·마감을 서버에서 차단하고, 정원 도달 시 `settling` 자동 전환 + 시스템 메시지 + 전원 알림.
  `participations` 에는 INSERT RLS 정책이 없어 클라이언트 직접 삽입이 불가능하다. **RPC 구현은 이슈 #5**.
- 자동 생성 트리거: 가입 시 `profiles`+`wallets` (#2 구현 완료).
  공구 생성 시 채팅방·주최자 참여·개설 시스템 메시지는 **이슈 #8·#9** 에서 추가한다
  (`chat_rooms` 에도 INSERT RLS 정책이 없다).
- 정산·지갑 RPC (**이슈 #15~18, 구현 완료**): `confirm_settlement`(총액 확정, 영수증 있으면 즉시 확정)·
  `finalize_settlement_vote`(영수증 없을 때 과반 동의 확정)·`adjust_participation_amount`(주최자 개별 조정,
  본인 몫은 나머지로 자동 계산)·`pay_with_wallet`(잔액 검증→차감→`is_paid`→`wallet_transactions`을 한
  트랜잭션으로 원자 처리)·`confirm_self_paid`(계좌·토스 셀프 체크)·`complete_group_buy_if_all_paid`(전원
  입금 시 `completed` 전환 + `trust_score` +1, 내부 전용)·`remind_unpaid`(주최자 전용 리마인드).
  시스템 메시지는 #9의 `post_system_message` RPC 를 호출해 기록한다 (문구는 `lib/sys-messages.ts`의 `sysText`와 일치).
- 소셜 로그인(Google·GitHub)은 Supabase Auth 가 처리하므로 **테이블 추가가 없다**. 제공자 계정은
  `auth.identities` 에 쌓이고, 어떤 제공자로 들어왔는지는 JWT 의 `app_metadata.provider` 로 읽는다.
  가입 트리거가 제공자별 메타데이터 키(`full_name`/`name`/`user_name`, `avatar_url`/`picture`)에서
  닉네임·아바타를 뽑아 `profiles` 에 채운다. 이메일 회원가입의 동네 인증 결과는 `dong` 에 저장된다
  (소셜 로그인은 동네 입력 단계가 없어 `null`).
- 세션 갱신은 `middleware.ts` 가 맡고, 소셜 로그인 콜백은 `app/auth/callback/route.ts` 에서
  `code` 를 세션 쿠키로 교환한다.
- 총 금액 변경은 RLS 로 **주최자 + `status='recruiting'` + 마감 전** 일 때만 허용 (정산 진입·마감 후 서버 거부).
- 시스템 메시지(`kind='sys'`)는 클라이언트가 삽입할 수 없고 서버 함수만 기록한다.
- 실시간: `group_buys`, `participations`, `messages`, `notifications`, `wallets`, `wallet_transactions`,
  `settlements`, `settlement_votes` Realtime 구독 (단일 출처는 `supabase/schema.sql` 6번 섹션)
- 영수증 이미지: Supabase Storage 버킷 `receipts` (자동 인식 없음, 참고용 첨부)

## 11. 데모 시나리오 (Day 3 리허설용)

1. 주최자가 배달음식 공구 공고 작성 (가게 링크 + 30분 마감) → 카드 미리보기
2. 참여자 2명이 목록에서 버튼 한 번으로 참여 → 진행바·1인당 금액 실시간 변동
3. 라운지에 공구 카드 공유 → 카드에서 세 번째 참여자 합류
4. 주최자가 총 금액 변경 → 전원 알림 + 재계산 확인
5. 정산 시작 → 총액 확정(수동 입력 + 영수증 사진 첨부) → 배달비 균등 1/N
6. 참여자 1명은 대파페이 자동 결제, 1명은 토스 링크 송금 → 체크리스트 갱신
7. 전원 입금 → 공구 `마감` + 신뢰도 배지 반영
