# 🎬 데모 대본 (docs/PLANNING.md 11번 기반)

> 리허설은 이 대본 순서 그대로, **배포 서버 기준**으로만 진행한다. 담당 배역을 미리 정해둘 것.

## 사전 세팅 (발표 30분 전)

- [ ] 계정 3개 로그인 상태로 브라우저 창 3개 준비 (주최자 / 참여자1 / 참여자2)
- [ ] 대파페이 잔액: 참여자1은 충분히, 참여자2는 부족하게 (충전 시연용)
- [ ] 라운지에 자연스러운 대화 몇 줄 미리 생성
- [ ] 백업 영상 로컬 저장 확인 (와이파이 사망 대비)

## 시나리오 (약 3분)

| # | 장면 | 배역 | 보여줄 것 · 멘트 포인트 |
| --- | --- | --- | --- |
| 1 | 배달음식 공구 작성 | 주최자 | 카테고리 선택 → 가게 링크·30분 마감 → **타이핑하는 대로 카드 미리보기가 변함** |
| 2 | 즉시 참여 ×2 | 참여자1·2 | 버튼 한 번 → **다른 화면의 진행바·1인당 금액이 실시간으로 움직임** (화면 2개 나란히) |
| 3 | 카드 공유 합류 | 주최자 → 참여자 | 라운지에 공구 카드 말풍선 → 탭 → 상세 → 참여 |
| 4 | 총 금액 변경 | 주최자 | 금액 수정 → **전원 알림 + 1인당 금액 재계산 + 시스템 메시지** 3종 세트 |
| 5 | 정산 시작 | 주최자 | 총액 확정(영수증 사진 첨부) → 금액 잠금 🔒 → 배달비 자동 균등 1/N |
| 6 | 입금 2가지 방식 | 참여자1·2 | 참여자1: 대파페이 원터치 / 참여자2: 토스 링크 → **체크리스트 실시간 갱신** |
| 7 | 마감 | 전체 | 전원 입금 → 공구 `마감` + 신뢰도 배지 → "총무 없는 공구, 끝났습니다" |

## 리스크 대응

| 상황 | 대응 |
| --- | --- |
| 서버/와이파이 사망 | 즉시 백업 영상으로 전환 (당황 금지, "녹화본으로 보여드릴게요") |
| 실시간 반영 지연 | 새로고침 금지 — 2초 기다리며 멘트로 연결 |
| 시연 중 버그 | 데모 시나리오 밖 기능은 절대 클릭하지 않는다 |
